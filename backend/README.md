# «Маяк» — backend

API народной карты Владивостока: локации с точными границами и места четырёх слоёв внутри них
(инфраструктура, события, туризм, проблемы), коллективная проверка, репутация, модерация,
маршруты, заметки на карте, импорт афиши и отключений из VL.ru, базовый слой объектов и территорий
из OpenStreetMap, места с описаниями из путеводителя Викигид, фото и описания из Wikimedia. Бизнес-правила — в [`docs/SPEC.md`](../docs/SPEC.md),
HTTP-контракт — в [`docs/API.md`](../docs/API.md).

Стек: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 (async) + SQLite, PyJWT, argon2, Pillow,
httpx, selectolax, shapely. Менеджер зависимостей — `uv`.

## Запуск

```bash
cd backend
cp .env.example .env          # впишите SECRET_KEY и, при наличии, ключи 2GIS и OpenRouter
uv sync
uv run uvicorn app.main:app --port 8000
```

При первом старте создаётся база `data/mayak.db` и заполняется демо-данными. Документация
API: <http://localhost:8000/docs>. Загруженные фото лежат в `media/` и отдаются по `/media`.

Демо-аккаунты (пароль у всех `mayak2026`): `admin@mayak-vl.ru`, `moderator@mayak-vl.ru`,
`expert@mayak-vl.ru`, `demo@mayak-vl.ru`, `resident@mayak-vl.ru`, `newcomer@mayak-vl.ru`.

В Docker:

```bash
docker build -t mayak-backend .
docker run -p 8000:8000 --env-file .env -v mayak-data:/app/data -v mayak-media:/app/media mayak-backend
```

## Команды

| Команда | Что делает |
|---|---|
| `uv run pytest -q` | тесты: чистый домен, парсеры на сохранённых страницах, API на временной базе |
| `uv run ruff check . && uv run ruff format --check .` | линтер и формат |
| `uv run python -m app.seed --reset` | пересоздать базу и заполнить демо-данными |
| `uv run python -m app.afisha_import` | разовый импорт афиши VL.ru |
| `uv run python -m app.outages_import` | разовый импорт отключений VL.ru |
| `uv run python -m app.osm_import [--fetch]` | импорт слоя OpenStreetMap из снимка; `--fetch` — сначала один запрос к Overpass и обновление снимка |
| `uv run python -m app.wikivoyage_import [--fetch]` | места и описания из Викигида из снимка; `--fetch` — сначала по запросу на статью и обновление снимка |
| `uv run python -m app.wikimedia_enrich [--fetch]` | фото Commons и описания Википедии из снимка туда, где их нет; `--fetch` — сначала собрать снимок пакетными запросами |
| `uv run python -m app.services.interests.classify [--limit N] [--rules-only]` | темы интересов (SPEC §23): разметить правилами всё новое и изменённое, затем отдать LLM до N ещё не размеченных мест, событий и локаций (по умолчанию 150, пачками по 15, в пределах суточного лимита) |
| `uv run python -m app.services.experimental.external_reviews.warmup [--limit 40]` | заранее найти внешние отзывы для самых заметных мест и локаций (те же лимиты) |
| `uv run python -m app.seed.fetch_route_paths [ключи]` | пересчитать геометрию демо-маршрутов (по умолчанию всех «по дорогам») |
| `uv run python -m app.routes_recompute` | перестроить линии всех маршрутов «по дорогам» в базе текущим маршрутизатором — после смены `ROUTING_PROVIDERS` |

Тесты не ходят в сеть: клиенты OSRM, 2GIS, OpenRouter, VL.ru, Overpass, Викигида, Wikimedia и внешних отзывов подменяются.

Импорты и обогащение работают и на давно запущенной базе: новые таблицы (`text_credits`,
`external_links`, таблицы интересов `interest_tags`, `interest_tag_states`, `user_interests`,
`user_interest_settings`, таблицы проверки `quiet_holds`, `place_quality`, `author_standing`,
`author_standing_events`) появляются при старте или при запуске любой из команд выше, существующие колонки не
меняются, повторный запуск ничего не дублирует. Порядок: `osm_import` → `wikivoyage_import` →
`wikimedia_enrich`.

## Настройки

Все переменные перечислены в [`.env.example`](.env.example). Главное:

- `ROUTING_PROVIDERS` — кто строит линии маршрутов «по дорогам», через запятую, по порядку
  (по умолчанию `osrm`). `osrm` — данные OpenStreetMap через публичный сервер OSRM от FOSSGIS
  (`OSRM_BASE_URL`, по умолчанию `https://routing.openstreetmap.de`, без ключа: не чаще запроса в
  секунду, ответы кэшируются). `2gis` — Routing API 2GIS, нужен ключ с маршрутизацией в подписке
  (`TWOGIS_API_KEY`). Если не ответил ни один, путь строится прямыми отрезками
  (`source: "straight"`). Геометрия сохраняется в маршруте; после смены маршрутизатора линии
  в базе перестраивает `app.routes_recompute`.
- `TWOGIS_API_KEY` — ключ 2GIS для агрегированного рейтинга мест и, по желанию, маршрутизации.
- `OPENROUTER_API_KEY` — проверка контента моделью до показа (SPEC §14, §24): всё, что публикует
  житель, сначала видит только он сам; текст проверяется одним запросом, каждое фото — отдельным.
  Не прошедшее остаётся видимым только автору (он об этом не узнаёт) и ждёт модератора. Модель только
  советует: не одобряет, не удаляет и не трогает репутацию. Без ключа (или по тайм-ауту 20 с, при
  исчерпанном `LLM_MODERATION_DAILY_LIMIT`) публикация выпускается сразу, если внутренняя оценка автора
  не ниже 30. Окна проверки, оставшиеся после перезапуска, досылаются при старте и раз в минуту.
- `AFISHA_IMPORT_ENABLED`, `OUTAGES_IMPORT_ENABLED` — фоновые импорты из VL.ru (афиша раз в
  12 часов, отключения раз в 20 минут; не чаще одного запроса в секунду, с соблюдением
  `robots.txt`). Сбой импорта не влияет на работу приложения.
- `OSM_BBOX` — территория слоя OpenStreetMap (юг, запад, север, восток) для `osm_import --fetch`.
  Само приложение читает только закоммиченный снимок `app/seed/osm_snapshot.json` и от Overpass не зависит.
- `TWOGIS_RATING_DAILY_LIMIT` — сколько раз в сутки можно спросить у 2GIS агрегированный рейтинг
  объекта (по умолчанию 30; кэш — неделя). Рейтинг показывается отдельной строкой и не смешивается с нашим.
- `EXTERNAL_REVIEWS_ENABLED` — отзывы Яндекса, 2ГИС и Google (SPEC §20) и сводный рейтинг `combined_rating`
  (SPEC §22), по умолчанию выключены. `EXTERNAL_REVIEWS_DAILY_REQUEST_CAP` — запросов к источнику в сутки
  (10 000); `EXTERNAL_REVIEWS_LLM_MODEL` / `EXTERNAL_REVIEWS_LLM_ENABLED` — LLM-проверка соответствия
  (по умолчанию `typesafe/jev-router`, включена при наличии `OPENROUTER_API_KEY`).
- `INTERESTS_LLM_ENABLED`, `INTERESTS_LLM_MODEL`, `INTERESTS_LLM_DAILY_REQUEST_CAP` — темы интересов от LLM
  для «Для вас» (SPEC §23): по умолчанию включено при наличии `OPENROUTER_API_KEY`, модель
  `typesafe/jev-router`, не больше 2000 запросов в сутки. Фоновая разметка идёт пачками по 15 объектов
  с паузой в несколько секунд, пока есть неразмеченные; без ключа или с `INTERESTS_LLM_ENABLED=false`
  работают одни правила (категория, вид локации, словарь ключевых слов). Модель видит только тексты
  объектов, её ответ недоверенный. Профиль интересов приватен: текст поиска не хранится, хранятся
  только итоговые числа по темам.
- Викигид и Wikimedia читаются только командами выше (не чаще запроса в секунду, фиксированный
  User-Agent без личных данных); приложение берёт данные из закоммиченных снимков.

Ключевые решения:

- **Статус и доверие** места пересчитываются одной функцией
  (`services/verification.recompute_place`) после каждого голоса, жалобы и решения
  модератора; формулы лежат в `domain/trust.py`. Затухание голосов во времени обновляется
  при старте (`refresh_trust_scores`).
- **Демо-данные** не записаны руками: сид проигрывает год жизни города через те же функции,
  что и API (голоса, жалобы, решения модератора, импорт отключений), поэтому статусы, история,
  события репутации и уведомления получены настоящими правилами. Все события, проблемы, отзывы
  и заметки в сиде вымышленные; координаты объектов сверены с OpenStreetMap.
- **Слой OpenStreetMap** импортируется пачкой: принадлежность к локациям считается через
  пространственный индекс, сводки локаций — двумя запросами на все локации, поэтому сид с ~3 400
  объектами OSM занимает секунды. OSM — источник с весом 1.0: объекты стартуют «предварительными»
  и подтверждаются жителями; места жителей в радиусе 40 м всегда побеждают.
- **Внешние данные** (страницы VL.ru, Overpass, OSRM, Wikimedia, Яндекс, ответы LLM и 2GIS) считаются недоверенными: разбираются
  парсером, приводятся к типам и проверяются по схеме, ничего из них не исполняется.

## Данные и лицензии

- Контуры локаций в `app/seed/area_polygons.json`, координаты объектов инфраструктуры и весь базовый
  слой `app/seed/osm_snapshot.json` (объекты и территории) получены из OpenStreetMap —
  © участники OpenStreetMap, лицензия ODbL (<https://www.openstreetmap.org/copyright>); подробности —
  в `app/seed/osm_snapshot.txt`. Производная от OSM часть данных остаётся под ODbL; контент жителей
  хранится отдельно. Приложение показывает атрибуцию на карточках мест и локаций из OSM. Контуры, найденные через
  `GET /areas/geometry-lookup?q=…`, тоже берутся из OSM (Nominatim) и отдаются с этой атрибуцией.
- Геометрия демо-маршрутов в `app/seed/route_paths.json` и линии новых маршрутов построены по данным
  OpenStreetMap сервисом OSRM от FOSSGIS (<https://routing.openstreetmap.de>) — © участники OpenStreetMap,
  ODbL; страница маршрута и версия для печати показывают атрибуцию.
- Афиша и отключения импортируются со страниц VL.ru со ссылкой на источник в каждой карточке.
- Места и описания из путеводителя Викигид (`app/seed/wikivoyage_snapshot.json`, подробности — в
  `wikivoyage_snapshot.txt`) — © авторы Викигида, CC BY-SA 4.0; каждый такой текст показывается с
  подписью «Текст: Викигид, CC BY-SA 4.0» и ссылкой на статью.
- Фото Wikimedia Commons и первые абзацы статей Википедии (снимок `app/seed/wikimedia_snapshot.json`
  собирает `app.wikimedia_enrich --fetch`) не копируются: отдаются ссылки на миниатюры Commons, у каждого
  фото есть `credit` — автор, лицензия и страница файла, у текста — «Текст: Википедия, CC BY-SA 4.0».
  Сейчас Wikimedia отвечает нашему клиенту 403 «Please respect our robot policy» (требует контакт в
  User-Agent), поэтому снимок не собран (SPEC §19).
- Агрегированный рейтинг 2GIS берётся через официальный Places API со ссылкой на карточку 2ГИС.

## Внешние отзывы

Включается `EXTERNAL_REVIEWS_ENABLED=true` (SPEC §20). Только по запросу карточки (строка-сводка и
фото-заглушка читают лишь кэш, списки источники не спрашивают никогда) и с кэшем на неделю, не чаще
одного запроса в 4 секунды и не больше `EXTERNAL_REVIEWS_DAILY_REQUEST_CAP` (10 000) в сутки на каждый
источник, без обхода защит: капча, редирект или код ошибки завершают поиск этого объекта (`blocked`),
ответ, который не удалось разобрать, — тоже (`failed`); объект спрашивается снова через час, остальные —
как обычно. Источник целиком не выключается никогда. Сбой транспорта (прокси, тайм-аут соединения,
оборванное соединение) повторяется один раз через новую прокси-сессию; отказ источника не повторяется. `EXTERNAL_REVIEWS_FAILURE_DUMP_DIR` сохраняет неразобранный ответ
для отладки (в сырых страницах есть имена авторов — вне отладки не задавать). Хранятся только оценка, текст (до 600 символов), дата и ссылка; данных авторов отзывов нет нигде.
Для демо-базы отзывы можно подготовить заранее: `uv run python -m
app.services.experimental.external_reviews.warmup --source all --limit 40` (по очереди, в тех же лимитах;
прогон останавливается на первом отказе источника или на суточном лимите).

`EXTERNAL_REVIEWS_PROXY_URL` задаёт HTTP(S)/SOCKS5/SOCKS5H-прокси только для этого эксперимента;
шаблон `{sid}` заменяется случайным идентификатором при создании клиента. URL с паролем хранится
в локальном `backend/.env` или переменных окружения, для Docker — в корневом `.env`.
Системные `HTTP_PROXY`/`HTTPS_PROXY` клиент не наследует. `EXTERNAL_REVIEWS_REQUEST_TIMEOUT_S`
задаёт тайм-аут запроса (по умолчанию 20 секунд). После изменения настроек нужен перезапуск backend.
При долгой загрузке API возвращает `pending=true` и `pending_sources` (какие источники ещё отвечают),
интерфейс проверяет готовность каждые 2 секунды; повторный запрос использует уже выполняющуюся задачу.

В одном ответе доступны тексты Яндекса, 2ГИС и Google: до 30 отзывов от каждого источника
из того же запроса (в проверенной анонимной сессии Google отдаёт 5), отдельные оценки и ссылки на оригинал.
«Показать ещё» (`…/external-reviews/more?source=2gis`) догружает следующую страницу — пока только для
объектов карты 2ГИС (`/3.0/geo/{id}/reviews`, свои `offset` и `limit=50`): один запрос в тех же
лимитах, отзывы дописываются к кэшу без повторов, не больше 200 на источник; позиция страниц и
потраченные запросы — в таблице `external_catalogue_cursors`.
Даты Яндекса и 2ГИС сохраняются; неподтверждённая точная дата Google остаётся `null`.
Загрузки идут параллельно; кэш и лимиты независимы. `EXTERNAL_REVIEWS_TWOGIS_ENABLED=false` и `EXTERNAL_REVIEWS_GOOGLE_ENABLED=false`
отключают соответствующие загрузчики отдельно.

2ГИС использует HTTP-интерфейс анонимного веб-клиента: публичные `webApiKey` и `reviewApiKey`
читаются с главной страницы и держатся в памяти до суток; ключ Places проекта не используется.
Каталог `/3.0/items` ищет по названию и координатам, `/items/byid` — по привязанному `object_id`;
запрос содержит контрольную сумму `r`, как в опубликованном веб-клиенте. Поиск может вернуть
ID с суффиксом отслеживания: для отзывов используется его числовая часть. При поиске выбирается
только однозначный результат по правилам сопоставления ниже; при наличии ID — только
эта организация с дополнительной проверкой координат.
`public-api.reviews.2gis.com/2.0/branches/{id}/reviews` возвращает последние отзывы с датой создания.
Мосты, скверы, набережные, сопки в каталоге — не организации, а объекты карты (`building`, `adm_div`,
`attraction`): если среди организаций нашего объекта нет, делается второй поиск по ним, а отзывы
читаются с `…/3.0/geo/{id}/reviews`. На один объект уходит до 4 запросов.
Парсер проверяет принадлежность организации, пропускает скрытые, модерируемые и повторные отзывы.
Ключи не зашиты в исходники. Изменение веб-интерфейса может потребовать обновления адаптера.

Сквозная проверка через SOCKS-прокси 2026-11-11: общий API на временной базе вернул для
Приморского океанариума по 10 отзывов Яндекса и 2ГИС с оценками и датами; повторное чтение кэша
совпало. Яндекс проверяет ID организации и отличает пустой список от отсутствующего блока данных.
Резервный рейтинг 2ГИС из существующего кэша связанного `object_id` (`reviews_available=false`)
доступен только при актуальном подтверждении соответствия места этой организации.
Это чтение не расходует дополнительную квоту Places API.

Google использует анонимный поиск `/search?tbm=map` с `q` и `pb`, затем POST
`/maps/_/MapsWizUi/data/batchexecute?rpcids=qv9Egd`. Сначала обычный запрос `/maps` получает
анонимные cookies; они остаются только в памяти клиента, с тем же прокси-сеансом. Ключ не нужен.
ID организации берётся из найденной карточки, а не из первого похожего идентификатора в JSON
(им может оказаться географическая область). Каждый отзыв проверяется по ID организации.
Для части мест RPC пуст, хотя поиск показывает рейтинг и число отзывов: такое место считается найденным,
в карточке — рейтинг и ссылка без текстов (`reviews_available: false`).
В проверке 2026-11-12 поиск нашёл Приморский океанариум и RPC вернул 5 текстовых отзывов.
Итоговая сквозная проверка общего API вернула сразу три источника (10 + 10 + 5 отзывов)
и подтвердила повторное чтение из кэша без запросов к площадкам.
Старый `listentitiesreviews` отвечает 404. Это предварительная выборка; пагинации нет.
Точные даты Google пока не сохраняются: относительное время не превращается в выдуманную дату.
Chromium/Playwright и генерация токенов проверок не используются. Протокол недокументированный
и может измениться; исследовательская справка: https://pimpinpumpkin.github.io/Vela/docs/spec/.

Сопоставление: похожее название или ближайший филиал не достаточны. Автоматически
принимается название без похожих соседних организаций — точное (регистр, ё, пунктуация и
порядок слов не важны) или наше с дополнением: все наши слова стоят до запятой, без другого
типа объекта и без слов заведения или подразделения («Приморский океанариум, экспозиционный
корпус», «Мемориальная подводная лодка С-56, музей» — да; «…, касса», «Кафе …» — нет).
Допуск по расстоянию: 50 м для места; для локации — её радиус + 300 м при точном названии и
радиус при дополненном; 1500 м для точного названия моста, набережной, улицы. Кассы,
подразделения, родительский парк, типовые названия и неоднозначные филиалы не получают чужие
отзывы. В спорных случаях остаются ссылки на поиск. Это эвристика, а не гарантия точности: в
карточках нет структурированных адресов, телефонов и сайтов для дополнительной сверки. В
частности, длинное название океанариума в Google принимается, а два корпуса в 2ГИС
(экспозиционный и дельфинарий) конкурируют между собой и не дают совпадения.
Для конкретного здания 2ГИС можно использовать существующий `object_id`.

Где правила воздерживаются, а источник что-то нашёл, решает LLM через OpenRouter
(`EXTERNAL_REVIEWS_LLM_MODEL`, по умолчанию `typesafe/jev-router`; без `OPENROUTER_API_KEY` или с
`EXTERNAL_REVIEWS_LLM_ENABLED=false` — только правила). Модель видит наш объект (название, место или
локация, категория, родительская локация) и до 20 кандидатов в пределах санитарного радиуса —
название, тип в каталоге, расстояние, число отзывов — и отвечает строгим JSON: номер кандидата или
`null`. Выбор всё равно проверяется по радиусу и не может быть нашей родительской локацией; любая
ошибка — «не найдено». Для 2ГИС модель видит организации и объекты карты вместе. Метод
(`llm_choice`, `llm_none`) записывается в подтверждение соответствия. Прежние ответы «не найдено»,
полученные одними правилами (`unconfirmed`), при включённой модели перепроверяются через час;
совпадения правил остаются в силе.

Сводный рейтинг `combined_rating` (SPEC §22) карточек и списков мест и локаций считается только
из кэша (без запросов к источникам) пачкой на страницу: `app/services/combined_ratings.py`,
формула — `app/domain/combined_rating.py`.

Таблица `external_review_match_evidence` сохраняет ID/название/координаты найденной организации,
метод сопоставления и снимок входных данных с версией правил. Старый кэш без такого подтверждения
скрывается сразу; название, координаты, родительская локация, радиус и привязка входят в проверку.
Загрузка и кэш фронтенда тоже различают версии карточки. Пересоздавать базу не требуется:
новая таблица создаётся при старте, прежние строки остаются для учёта лимита запросов.

Для дополнительных источников созданы таблицы `external_catalogue_sources`,
`external_catalogue_reviews` и `external_catalogue_cursors`. Они создаются через `create_all` при старте; существующие таблицы
и кэш Яндекса не требуют пересоздания. CLI поддерживает `--source yandex`, `--source 2gis`,
`--source google`, `--source all` (по умолчанию); лимит объектов применяется к каждому выбранному источнику.

Чтобы удалить внешние отзывы: папку `app/services/experimental/external_reviews/`, строку
`include_router(external_reviews_router)` с импортом и зависимость `_bind_combined_ratings` в
`app/api/v1/__init__.py`, `app/services/combined_ratings.py`, `app/domain/combined_rating.py`, поля
`combined_rating` в схемах мест и локаций, настройку
`external_reviews_enabled` в `app/core/config.py` и обоих `.env.example`, тесты `tests/experimental/` и
фикстуры `tests/fixtures/yandex/` и `tests/fixtures/google/`, раздел в `docs/API.md`; таблицы `external_review_sources` и
`external_reviews` удалить из базы (`DROP TABLE external_reviews; DROP TABLE external_review_sources;`).
Также удалить таблицы `external_catalogue_reviews`, `external_catalogue_cursors`,
`external_catalogue_sources` и `external_review_match_evidence`.
На фронтенде — папку `features/places/external/` и места подключения (см. `frontend/README.md`).

## Ограничения

- SQLite и ограничитель частоты в памяти рассчитаны на один процесс.
- Капча без состояния: токен можно использовать повторно в течение пяти минут.
- Нет e-mail-подтверждения, push-уведомлений и миграций схемы (`create_all` при старте):
  после изменения моделей базу нужно пересоздать командой сида.
